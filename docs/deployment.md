# Netlify deployment

Hosting target: Netlify. Redis, Turnstile and Firebase App Check have not yet been provisioned. The Firebase project and production domain still need to be selected. No production infrastructure was changed by the implementation.

1. Connect this repository to the intended Netlify site. Keep the automatic Next.js adapter, `pnpm build`, `.next` publish directory and Node 24 from netlify.toml. Do not add a blanket SPA redirect. Set SITE_URL to the canonical HTTPS origin; use distinct preview configuration and Redis namespaces.
2. Provision an Upstash-compatible Redis REST database. Add its HTTPS URL and token to Netlify secrets. All production instances must use the same namespace. Keep the token and TMDB key server-only. The application deliberately refuses protected operations when Redis is missing or unavailable.
3. Verify Netlify overwrites `x-nf-client-connection-ip` with the actual connecting address, including requests carrying forged copies of that header and `x-forwarded-for`. Only then set TRUSTED_CLIENT_IP_HEADER. Without it anonymous traffic shares a fallback bucket. Confirm there is no alternate ingress bypassing the trusted proxy.
4. Register a Turnstile widget for the canonical hostname. Set public site key, private secret and TURNSTILE_HOSTNAME. Preview domains need their own allowed configuration. The server checks action `search`, hostname, token age and atomic single-use consumption. After eight searches/minute the challenge is requested; without configured keys this becomes a temporary 429 instead of permitting unverified traffic.
5. Select the Firebase project. Enable desired email/password, Google and GitHub providers, set authorized domains and OAuth callback settings, and add the four public Firebase values in .env.example. Configure recovery email templates and Firebase authentication abuse controls. These browser configuration values are identifiers, not database authorization.
6. Review existing data/clients, then publish firestore.rules to that verified project after publishing the updated client. Example: `pnpm exec firebase deploy --only firestore:rules --project YOUR_VERIFIED_PROJECT_ID`. Rules deny other paths; assess any unrelated project clients before deploying. Never use a guessed project ID.
7. Register the web app with Firebase App Check using reCAPTCHA Enterprise. Set NEXT_PUBLIC_RECAPTCHA_ENTERPRISE_SITE_KEY before the Netlify build. Observe valid/invalid traffic, then enable enforcement for supported services, including Firestore. Verify login, refresh, reads and writes on mobile and desktop before enforcement. App Check is not a substitute for ownership rules.
8. Run `pnpm check:deployment` with hosting environment exported (or `node --env-file=.env.local scripts/check-deployment.mjs`). It validates configuration shape, never prints secret values, and does not verify service activation. Public environment changes require a rebuild.
9. Configure available Netlify edge firewall/rate controls for `/api/search`, dynamic pages and image transformations; check plan availability. Configure Firebase, Redis, TMDB and hosting usage alerts/quotas. Billing alerts do not impose a hard spending cap. Set and document log retention, data deletion/contact procedures and privacy text for the actual operator.
10. On staging, verify burst and sustained 429 responses with Retry-After, shared limits across instances, invalid/replayed challenges, Redis outage behavior, forged headers, CSP console violations, OAuth popup recovery, owner/cross-user access and App Check rejection. Test live trailer and availability links. Run mobile/desktop accessibility and production performance checks, then record results before launch.

The local application builds successfully without credentials. This is not evidence that a deployed site is ready: protected production pages remain unavailable until Redis and TMDB are configured.

References: [Netlify Next.js integration](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/), [Turnstile validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [Firebase App Check web](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider).
